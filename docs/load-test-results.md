## Trial 1: Aurora ウォームアップ（5ユーザー / 90秒）

Aurora Serverless v2 のコールドスタートを観測し、ウォームアップで解消することを確認した。

| エンドポイント | avg (ms) | 備考 |
|--------------|----------|------|
| /motorcycles [warmup] | **14,910** | Aurora コールドスタート（約15秒） |
| /motorcycles（ウォームアップ後） | 12 | 正常応答 |
| /health | 7 | - |
| /motorcycles/{id}/chain-stats | 15 | - |

**結論:** Aurora のコールドスタートは約15秒。ウォームアップリクエストで事前に吸収できる。

|------|-----|

## 考察

### I/O バウンドアプリの CPU スケーリング限界

CRUD アプリで Aurora を使う場合、**Aurora 接続プールの枯渇が CPU 60% より先にボトルネックになる**。
結果として、負荷を増やしても CPU が上がらず Auto Scaling が発火しない。

| 症状 | 原因 |
|------|------|
| 100ユーザーで CPU が下がる | リクエストが DB 接続待ちで I/O ブロック |
| 500 / 504 エラー | SQLAlchemy 接続プール枯渇 → タイムアウト |

### 実運用での推奨

| 課題 | 対策 |
|------|------|
| DB 接続枯渇 | **RDS Proxy** 導入（接続を多重化） |
| CPU 以外でのスケーリング | リクエスト数ベースのカスタムメトリクス |
| コールドスタート対策 | 定期的なウォームアップリクエスト（CloudWatch Events 等） |
