# 要件定義 - Bike Specs Lookup App

## プロジェクトの目的

AWS上でRDS・HTTPS・Auto Scalingの各要素を実地検証するための学習台として、
バイクのスペック情報（排気量・チェーン・スプロケット）を検索できるWebアプリを構築する。

**本プロジェクトの主目的は技術検証であり、アプリ機能そのものではない。**
ただし「動くだけ」で終わらせず、ポートフォリオとして提示可能な完成度を目指す。

> **ピボット履歴**: Phase 1 ではチェーンメンテ記録アプリとして実装したが、Phase 3-B にて
> 「バイクスペック検索サービス」へピボット。DB設計・API・フロントエンドをすべて刷新した。

## 機能要件

### MVP（実装済み）

| ID | 機能 | 概要 |
|---|---|---|
| F-01 | メーカー一覧取得 | DB登録済みメーカー名の一覧を返す |
| F-02 | 排気量一覧取得 | 指定メーカーの登録排気量リストを返す |
| F-03 | バイク一覧取得 | メーカー・排気量範囲でフィルタリングしたスペック一覧を返す |
| F-04 | チェーン統計取得 | 指定バイクのチェーン1周あたりの後輪回転数を算出して返す |
| F-05 | スペック検索UI | Alpine.js + Tailwind CSS によるシングルページUI |

### スコープ外（意図的に実装しない）

- ユーザー認証・マルチユーザー対応：学習スコープ外
- メンテ記録の管理機能：ピボットにより廃止
- 車種マスタの管理UI：スクレイパー + CSVで管理

## 非機能要件

| 観点 | 目標値 | 備考 |
|---|---|---|
| 可用性 | 99%以下で可 | 学習用途、SLA不要 |
| レスポンスタイム | API応答 < 500ms | スペック検索は単純なSELECTのため余裕 |
| 同時接続数 | 10 req/s処理可能 | Auto Scaling検証時の負荷試験基準 |
| 月額コスト | 5,000円以下 | 学習完了後は停止してコストゼロ化 |
| セキュリティ | HTTPS必須、DB情報はSecrets Manager管理 | 平文DB接続情報はコードに書かない |

## 計算式仕様

### チェーン1周の後輪回転数

```
後輪回転数 = チェーンコマ数 / (リアスプロケ丁数 × 2)
```

**根拠**:
- チェーン1コマ = 1/2インチ（ANSI規格）
- リアスプロケは1歯あたりチェーン1コマと噛む
- リアスプロケ1回転でチェーンは「丁数 × 2コマ」進む
- したがって、リアホイールが `チェーンコマ数 / (丁数 × 2)` 回転でチェーン1周

**例）** MT-09 SP（リアスプロケ45T、チェーン118L）の場合:
`118 / (45 × 2) ≈ 1.31 回転` → リアタイヤのエアバルブを基準に約1周と1/3回したらチェーン1周。

## データ管理方針

- スペックデータは `scripts/scrape_maker.py` で [バイクブロス](https://www.bikebros.co.jp) からスクレイピング
- スクレイピング結果は `data/bike_masters.csv` としてリポジトリにコミット
- Alembicマイグレーションがデプロイ時にCSVを読んでDBへシード
- データ更新手順: スクレイプ → CSV更新 → PR → デプロイ で完結
